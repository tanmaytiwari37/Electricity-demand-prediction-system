# PeakWatch Delhi - Architecture

```
                         USER (DISCOM / SLDC operator)
                                    |
                                    v
                    React dashboard  (frontend/, Vite + Tailwind + Recharts)
                    pages: Overview, Forecast, Alerts, Areas, Weather, What-if, Model
                                    |  REST  /api/*   (frontend/src/services/api.ts)
                                    v
                    FastAPI  (backend/main.py -> routers/ -> services/)
        +----------------+----------------+----------------+----------------+
        v                v                v                v                v
 forecast_service   alert_service   feeder_service   whatif_service   weather_impact_service
        |                                                    |
        v                                                    |
   ml/inference/DemandPredictor  <---- ml/models/*.joblib <--+-- ml/training (scripts/train_model.py)
        |
        v
   data_store: history (REAL CSV via PEAKWATCH_HISTORY_CSV, or SIMULATED demo generator)
               + weather forecast (Open-Meteo LIVE -> CACHE -> DEMO / HISTORICAL ANALOG)
```

## Data provenance

| Label | Meaning | Where it appears |
|---|---|---|
| REAL | Public data from a real source | Open-Meteo weather, Indian public holidays, the operator's demand CSV |
| SIMULATED DEMO | Generated by `ml/demo_data.py`, calibrated only to public ranges | Demo history, DISCOM split, feeder capacities |
| MODEL PREDICTION | Output of the trained model | Forecast, bands, peak, alerts, what-if |
| HEURISTIC | Same-hour-last-7-days estimate used when no model is loaded | Forecast until the demo model finishes training |
| ASSUMPTION | Editable demo parameter | Grid capacity 9,200 MW (planning assumption), risk thresholds 85/92/97 %, solar profile |

Every API response carries `data_source` (history provenance) and, where relevant, `forecast_method`,
`weather_source` and `allocation`. `/api/status` bundles them for the header badges.

## Endpoints

| Method | Path | Purpose |
|---|---|---|
| GET | `/api/health` | liveness, model status |
| GET | `/api/status` | provenance, freshness, assumptions, model card |
| GET | `/api/model` | metrics, baselines, feature importance |
| GET | `/api/forecast?horizon=24..168&capacity_mw=` | hourly forecast with band and peak |
| GET | `/api/actual?hours=48` | recent actuals with 1-hour-ahead backtest |
| GET | `/api/alerts?horizon=&capacity_mw=` | risk level, headroom, alert windows |
| GET | `/api/feeders?ts=&horizon=&capacity_mw=` | DISCOM/area utilisation and hourly heatmap |
| GET | `/api/weather-impact` | temperature-load statistics from history |
| POST | `/api/whatif` | temperature shift + rooftop solar scenario |

## ML pipeline (`ml/`)

CSV -> `data/loader.py` (aliases, schema check, IST timestamps, hourly regularisation, gap fill <= 3 h, outlier flags, report)
-> `features.py` (calendar, weather, lags 1/24/168 h, rolling means; all shifted so nothing at or after t leaks in)
-> `training/train.py` (chronological train/val/test, baselines, HistGradientBoosting vs RandomForest, selection by validation MAE,
permutation importance, residual P10/P90 for bands, refit on train+val, artifact)
-> `inference/predictor.py` (recursive multi-step forecast using the weather forecast frame).

## Failure behaviour

| Failure | Behaviour |
|---|---|
| No real CSV | DEMO MODE: simulated history, badge shows SIMULATED DEMO |
| No trained model | heuristic forecast, labelled HEURISTIC; demo model trains in background |
| Open-Meteo down | cached forecast if < TTL, else simulated / historical-analog weather; badge changes |
| Backend down | frontend shows an error banner with retry; no fake data is shown |
